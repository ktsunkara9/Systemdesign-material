S — Single Responsibility: A class should have one responsibility and one reason to change.
O — Open/Closed: Software should be open for extension but closed for modification.
L — Liskov Substitution: A subclass should be replaceable for its parent without breaking the program's behavior.
I — Interface Segregation: Clients should not be forced to depend on methods they don't use.
D — Dependency Inversion: High-level code should depend on abstractions, not concrete implementations.
